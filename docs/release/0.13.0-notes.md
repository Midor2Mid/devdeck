# 0.13.0 — the GitHub release body

**Not published.** `product-director`'s 0.13.0 ruling (ROADMAP, 2026-09-04) is *cut
it, publish nothing until step 4 lands*. This file is the body to paste when the
recreated remote gets its first release; it is written now because the knowledge is
perishable and the people who did the work still have it.

## Why this is not `CHANGELOG.md`'s text

The ruling says so directly — *"`CHANGELOG.md` is not that text"* — and the harvest
of the 14 published releases proves why: six of eight distinctive paragraphs in
0.10.0's release body appear nowhere in this repo. A GitHub release body and a
changelog entry are different documents with different readers.

- **The changelog entry covers 0.13.0.** Its reader has the three entries above it
  and can scroll. Repeating 0.11.0, 0.11.1 and 0.12.0 inside the 0.13.0 entry would
  make the file lie about which version shipped what.
- **This body covers four versions**, because its reader last saw **0.10.0** and
  everything since arrived in one installer. Same rollup shape 0.10.0's own body
  used for 0.9.0 / 0.9.1 / 0.10.0.
- **This body carries what a changelog has no place for**: which file to download,
  what SmartScreen will do, and that `latest.yml` must be attached or every existing
  install stops updating.
- It is roughly a fifth the length. A release body is read once, on the way to a
  download button.

**Before publishing, check three things are still true:** the version numbers below
match the tag; the signature paragraph still describes the certificate the build was
actually signed with (it is written for the self-signed one — if step 6's trusted
certificate has landed by then, that paragraph is wrong and must be rewritten); and
the phone card has or has not been verified on hardware (ROADMAP step 7), because the
last section states that it has not.

# Release body — paste below this line

**DevDeck 0.13.0 — the release that removes things**

> The first published build since **0.10.0** — it carries **0.11.0, 0.11.1, 0.12.0
> and 0.13.0** in one installer. Six surfaces and 78 of the 84 skins are gone, and
> the crash that could make DevDeck unopenable is fixed.
>
> ## A project whose folder had moved took the app down, and kept it down
>
> Opening a terminal in a project whose folder had been moved, renamed or unmounted
> killed the main process — and the tab that did it was saved, so every later launch
> died before the UI loaded, with hand-editing files under `userData` as the only way
> back. node-pty's Windows agent raises error 267 for a bad working directory
> *asynchronously*, outside the guard that was there for the synchronous case. Three
> fixes: the directory is checked before anything is spawned; a tab that never started
> is no longer restored (a shell you ran and exited still comes back — restoring the
> arrangement is the feature); and an uncaught throw anywhere in the main process is
> now recorded into the diagnostics record and quits through a real teardown instead
> of showing Electron's "A JavaScript error occurred" dialog and leaving nothing on
> disk.
>
> ## Six surfaces and 78 skins are gone, and that is the feature
>
> Every UI change had to be verified against the skin matrix, and 84 combinations is
> what made each one expensive — a label change in this same round overflowed the
> app's own minimum window in one style, and nothing short of measuring all twelve
> would have found it. **84 skins → 6**: Slate, Washi and Sumi across Modern Pro and
> Wabi-sabi. A `settings.json` naming a deleted skin falls back to the default; your
> accent survives.
>
> Deleted with it: the **Network view and its local capture proxy** (a general-purpose
> forward proxy with no agent edge — Fiddler and browser devtools own that job),
> **ReleaseBoard**, **StandupModal**, **DotnetPanel** (and `Ctrl+Shift+B`), **terminal
> recording**, and the **Canvas terminal layout** (a `workspace.json` naming it opens
> on Grid). Deck view keys: eight → seven.
>
> **`Settings → Corporate proxy` is untouched.** It is a different feature that
> happens to share a word — the upstream proxy applied to every child DevDeck spawns
> so `npm`, `git` and `dotnet` work behind a firewall.
>
> ## The path a stranger walks now has labels on it
>
> All seven deck keys carry their name, where before only the active one did — which
> spent the label on the view you already knew. A key that is off can now be named by
> hovering, by Tab or by a screen reader, which a `disabled` button cannot be. There
> is an application menu with **`Ctrl+O`** and a **visible** menu bar, where before
> Electron's default menu made the first thing a Windows user tries a dead end. One
> verb, **`Open folder…`**, replaces five labels for the same act. Dragging a folder
> onto the window now works — it had animated on drag and done nothing since Electron
> 32 removed the property it read. A pane says which process it is waiting for instead
> of showing a black rectangle for a measured 4–12 seconds. Ten modals no longer blank
> the window when they throw.
>
> And a project whose folder is not there says so — three states, `ok` / `missing` /
> `unchecked` — instead of three separate features misattributing the failure to
> whatever you clicked next. A missing project still opens, because a path can come
> back.
>
> ## Answer a permission prompt from your phone (0.11.0)
>
> An agent that stops to ask permission used to reach a paired phone as the word
> "attention" and nothing else. The question now travels with it, with the raw screen
> it was read from underneath — the question is the one string an agent controls. A
> decision is bound to the screen that produced it and spent once: answer at the desk
> and every paired phone drops the card; tap a card whose terminal has moved on and
> the answer is refused rather than fired into whatever the agent asked next.
> **This card has never rendered on a physical phone** — see the last section.
>
> ## The app stops claiming things it does not know (0.12.0)
>
> A preset whose command is not on your PATH used to launch anyway, silently: the pane
> opened, DevDeck registered an agent session and rendered it as *waiting* while the
> shell printed "not recognized" into it. A three-state presence probe now resolves
> against **your shell's** PATH rather than the app's, because those are not the same
> PATH and reading the wrong one reports a working agent as missing. It marks, it does
> not gate — a PATH walk cannot see a shell alias.
>
> And when something breaks you can hand someone the reason: a capped, deduped,
> redacted diagnostics record with a *Copy diagnostics* button. **Nothing is sent
> anywhere** — no endpoint, no telemetry, no upload. It goes to your clipboard, and
> "Show what's copied" shows the record rather than a description of it.
>
> ## Safety, and words that matched what the button did
>
> - **`Claude YOLO` is now `Claude (no permission prompts)`**, marked `SKIPS PROMPTS`.
>   It runs `--dangerously-skip-permissions`; the only previous marking was a 2px
>   stripe and a tooltip.
> - **Dispatching a task no longer creates a git worktree by default.**
> - **A double-click no longer starts two paid agent sessions.**
> - **Deny sent a different keystroke on a phone than at a desk** — at 46 terminal
>   columns it stopped sending Esc and started sending the "No, and tell Claude what
>   to do differently" digit, which is a different thing to do to a live agent.
> - **An unreadable `projects.json` no longer looks like a fresh install**, where
>   before every project action silently did nothing, forever, with no explanation.
> - **Self-signed HTTPS stopped claiming to unlock mobile push** (0.11.0). It does
>   not: clicking through the browser warning marks the origin insecure, so service
>   workers and Web Push stay unavailable.
>
> **1,657 tests, typecheck at zero.**
>
> ## What this build does not do
>
> The phone approve/deny card **has never rendered on real hardware**. Its defects
> were found and fixed under Chrome's device emulation against a real prompt from a
> real terminal, which is not the same thing, and three known findings are explicitly
> not settled by it.
>
> No external user has ever run DevDeck — no install off the author's machine, no
> recorded first session. Nothing here is validated by anybody else yet.
>
> ---
>
> **Installers are signed with a self-signed certificate** (personal use), so
> SmartScreen will warn on first run. DevDeck is **Windows-only** on purpose, and you
> install the agent CLIs (Claude Code, Codex, Gemini) yourself — DevDeck runs them, it
> does not bundle them. Download `DevDeck-Setup-0.13.0.exe` to install, or the
> portable build to run without installing. `latest.yml` and the `.blockmap` must stay
> attached: `electron-updater` reads the manifest to find the download, and without it
> every existing install silently stops updating.
