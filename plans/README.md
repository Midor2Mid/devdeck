# Animation improvement plans

Generated by the `improve-animations` skill from a motion audit of
`src/renderer/src` at commit **8e7f85d**. DevDeck's motion layer is already
strong (custom curves on modal/drawer, real press feedback, 13
`prefers-reduced-motion` gates, no `transition: all`, no `scale(0)`); these
plans address the two highest-leverage findings: easing cohesion and progress
compositing.

Each plan is self-contained — exact file paths, current code, target values,
and a feel check. Any agent (including a cheaper model) can execute one without
further context.

| # | Plan | Severity | Category | Status |
|---|------|----------|----------|--------|
| 001 | [Consolidate overlay entrance easing onto one `--ease-out` token](001-consolidate-entrance-easing-tokens.md) | MEDIUM | Cohesion + Easing | DONE |
| 002 | [Animate progress fills on the GPU (`width` → `transform: scaleX`)](002-gpu-composite-progress-fills.md) | MEDIUM | Performance + Easing | DONE |

## Recommended execution order

1. **001** — highest leverage (touches every overlay the user sees); pure
   `styles.css` change.
2. **002** — perf win on the replay hot path; `styles.css` + two TSX files.

## Dependencies

None. The two plans touch disjoint rules/files and can run in either order or in
parallel. Both are CSS/style-prop only — no markup, no dependencies, and both
leave the `prefers-reduced-motion` behavior unchanged.

## Not turned into plans (from the audit)

- **Tooltip warm-up** (LOW): tooltips re-wait 420ms and re-animate across
  adjacent toolbar buttons. Timer logic, not a token swap — deferred.
- **`--ease-spring` dead token** (LOW): defined at `styles.css:55`, unused.
  Either remove or spend on a delight moment.
- **Toast stack has no exit + reflow teleports** (missed opportunity): a full
  fix needs FLIP-style layout animation, non-trivial in pure CSS with no motion
  library — deferred pending a decision.
